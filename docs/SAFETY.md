# OpenQuest Safety Policy

OpenQuest sends users outdoors to complete quests. We take safety seriously.

This document covers:
1. Quest safety filter (the regex net over LLM output)
2. Photo verification safety (GPS override)
3. Lockout safety (panic PIN, emergency calls, unlock fallback)
4. Privacy posture (what we collect, what we don't)

## Quest safety filter

Every quest prompt generated by the LLM passes through `lib/ai/safetyFilter.ts`
before being shown to the user. The filter rejects prompts that match any of
these categories:

| Category             | Example rejected phrases                                            |
|----------------------|---------------------------------------------------------------------|
| Trespassing          | "climb over", "private property", "enter the yard"                  |
| Traffic danger       | "stand in the road", "cross the highway", "walk on the freeway"     |
| Water hazard         | "swim", "wade", "cross the river", "dive in"                        |
| Heights              | "climb", "scale", "ledge", "rooftop", "balcony railing"            |
| Animal handling      | "catch", "pet", "feed the", "approach the deer"                     |
| Foraging            | "eat", "taste", "harvest", "pick and eat", "ingest"                |
| Strangers           | "ask a stranger", "follow someone", "photograph a person"           |
| Abstract             | "feel the breeze", "essence of", "shimmer", "spirit of"            |
| Self-harm           | "cut yourself", "hurt yourself", "self-harm"                        |
| Illegal             | "steal", "shoplift", "vandalize", "break in"                        |

If the filter rejects a prompt, the quest falls back to a hardcoded
template from `features/quests/fallbacks.ts`.

## Photo verification

The photo judge (Gemma multimodal) returns `{passed, reason, observations}`.
But the model's verdict is advisory — we run a GPS override check first:

1. If the photo's EXIF GPS is **outside** the quest radius → **FAIL**
   regardless of what the model says. The model can hallucinate that
   a stock photo matches; GPS doesn't lie.
2. If the photo's EXIF GPS is **within** the quest radius → defer to
   the model's verdict.
3. If GPS is **unavailable** (EXIF stripped, geolocation denied) →
   defer to the model's verdict, but log `gpsProximity: 'unknown'`
   so the user can see this in the verify result screen.

## Lockout safety

### Emergency calls

Emergency calls (911/112/999/etc.) go through the cellular modem, not
VpnService. They are **always reachable** during a lockout, even when
the companion is running. This is by design — Android does not let
VpnService block emergency calls.

The companion's allowed-domains list does NOT include any telephony
domains — telephony isn't IP-based, so it bypasses the VPN entirely.

### Panic PIN

Every user must set a 4-digit panic PIN during onboarding (or skip with
a warning that they can't force-unlock). Entering the PIN force-unlocks
the phone for 24 hours.

**Storage:**
- The PIN is NEVER stored in plaintext.
- We store `SHA-256(pin + ':' + deviceSalt)` in EncryptedSharedPreferences.
- `deviceSalt` is a per-install random 32-byte value.
- EncryptedSharedPreferences uses AES-256-GCM via the Android Keystore.
  On devices with a TEE/StrongBox, the encryption key never leaves the
  secure enclave.

**Recovery:**
- Lost your PIN? Uninstall the companion app. That clears the
  EncryptedSharedPreferences, the device salt, AND stops the
  foreground service — phone is unlocked immediately.

**Why 24 hours, not permanent?**
- If we let the panic PIN permanently disable lockouts, the user would
  just use it every time and the consequence mechanic would be dead.
- 24 hours is long enough to handle any real emergency (hurt, lost,
  need directions, kid is sick) but short enough that the user can't
  just panic-unlock every quest.

### Auto-expire

Every lockout has a maximum duration (default 60 minutes, capped at 120
minutes by the protocol). When the timer expires, the companion
auto-stops the VpnService and unlocks the phone. This is a hard
guarantee — the user cannot be locked out indefinitely.

### Reboot safety

MVP behavior: if the phone reboots during a lockout (battery died,
user forced a restart), the phone unlocks on reboot. We lose state
on reboot, which is the safe default — losing state means the phone
is usable.

(Stretch goal: persist lockout state to SharedPreferences and resume
after reboot via BootReceiver. Not in MVP.)

### Uninstall safety

If the user uninstalls the companion during a lockout, Android
automatically stops the foreground service and tears down the VPN.
The phone is immediately usable. There's no scenario where uninstalling
leaves the phone in a locked state.

## Privacy posture

### What we collect

- **Nothing by default.** Solo mode (PWA + companion) is fully offline.
  No telemetry, no analytics, no account.
- **If you opt into cross-device sync** (the Cloudflare Worker):
  - GitHub ID and login (for account identity)
  - Quest metadata (prompt, place, category, status, timestamps)
  - Photos (in R2, used for the phone↔laptop judging flow)

### What we don't collect

- **Your GPS coordinates.** The PWA uses `navigator.geolocation` to
  fetch nearby POIs from Overpass, but the coordinates are used
  in-memory only — never stored, never uploaded.
- **Your browsing history.** The companion's VpnService drops packets,
  it doesn't log them.
- **Your PIN.** We store a salted SHA-256 hash. The PIN itself never
  leaves the input field.

### Account deletion

If you used cross-device sync, you can delete your account from the
PWA's settings. This purges:
- All `finds` rows for your user (D1)
- All photos for your finds (R2)
- All `daily_completions` rows
- All `sessions` for your user
- Your `users` row

The deletion is irreversible and immediate.

## Honest limits

- **Power user can bypass the lockout.** Someone with developer tools
  can call `companionBridge.unlock()` from the PWA's devtools console.
  If you're going to that effort, you weren't the target audience.
- **GPS spoofing is possible on rooted phones.** We accept this —
  the photo judge catches most fakes anyway, and we're not trying
  to defeat determined cheaters, just your own doomscrolling habit.
- **The LLM can hallucinate.** Small models (Gemma 3B-class) sometimes
  approve photos that don't match. The GPS override catches the worst
  cases (photo taken at the wrong location), but a determined user
  could photograph a screen showing the right thing. We accept this.
